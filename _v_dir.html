beeWork

Your work hours, recorded as you work — no timesheet.

Clock in, start a session, and get on with your day. beeWork records your working day and syncs it quietly from the system tray.

  • Windows desktop app
  • Update check
  • Runs in the tray

Opening frame in one sentence: beeWork records working hours as the day goes on, so staff never fill in a timesheet. It runs quietly in the tray and syncs in the background.

The problem

Manual timesheets are guesswork.

01

Nobody remembers the day

Hours are entered at 6pm from memory — often rounded, rarely accurate.

02

No view of where time went

Which client, which project, how long on each — it's all a blank once the day ends.

03

Admin work steals billable time

Filling in forms is unpaid overhead that nobody enjoys.

04

No proof of the working day

Without a record, hours can't be checked or backed up.

Set up the pain before the pitch: manual timesheets are inaccurate, admin-heavy and impossible to verify. Land the point that the data already exists on the machine — someone just has to capture it.

The idea

One loop, from clock-in to clock-out.

beeWork turns a working day into a record — with almost no input from the user.

1Clock in
→
2Start session
→
3Work as usual
→
4Auto-sync
→
5Review summary
→
6Clock out
  • Almost zero input — pick a client, a project and a task, then start.
  • Capture happens in the background — logs sync while the session runs.
  • Ends itself — clocking out on BeeWhere ends the session automatically.

The whole interaction is a few clicks at the start of the day — the rest is automatic.

The core narrative: one simple loop. Emphasise that steps 3 and 4 require nothing from the user — that's the whole value proposition versus a timesheet.

The product

Everything the app does.

⏱Session recording

Start a session and your working hours are recorded as you work, with active and idle time separated.

🏷Client & project tagging

Every session is filed against a client and project, with the task you were working on.

📋Work log

A running record of the applications and windows used, each marked synced or pending.

📊Usage summary

A daily breakdown: total active time, time per application, and top sites visited.

🔔Tray status

Lives in the Windows notification area — left-click to open, no window clutter.

🔄Update check

Checks for new versions automatically and notifies you. You choose when to download and install.

Capability map: keep it to six. Recording, tagging, logs, summary, tray, updates. These map directly onto the screens in the user manual.

Transparency

Users know what's recorded.

  • On first launch, a company notice explains exactly what the app records.
  • Workflow activity — the applications and tools used to get work done.
  • Focus status — active work periods and breaks through the day.
  • Time allocation — how time is distributed across tools.
Read the notice, then click "I Acknowledge and Continue" — shown once, never again.
Trust slide. Lead with transparency — the user is told upfront what is recorded and why. This is the slide to use if anyone raises privacy concerns.

Getting in

Sign in with a company account.

2Tick "Remember me" to save credentials
3Click Login

Previously used accounts appear for one-tap autofill. It's the same account issued by the company.

Simple onboarding. Note that accounts are company-issued — no separate signup. "Remember me" saves re-typing for users on shared machines.

The daily flow

Start a session in five steps.

1Clock in for the day (required)
2Select a client
3Select a project
4Type the task and press Enter
5Click Start session
Client and project are both required — and at least one task.
Walk the steps left to right. Stress the clock-in requirement — users who hit "Clock In Required" skipped step one. After starting, the window minimises to the tray.

Out of the way

Runs quietly in the tray.

  • Left-click the tray icon to reopen the app.
  • Right-click for Exit.
  • No window clutter — the app never blocks the desktop.

The icon stays visible for the whole session, so users can tell at a glance that recording is active.

This is the "it doesn't get in the way" slide. Non-intrusive by design — the tray icon doubles as the recording indicator.

Live status

Work Session Assistant.

  • A live elapsed clock for the current session.
  • Active vs. idle time, broken out.
  • Whether logs are pending or synced.

Open it from the tray at any point during the day to confirm recording is running.

The live status view. Useful for the demo — open from the tray and show the clock ticking and the sync state changing from pending to synced.

The record

Work log and the daily summary.

Recent Work — application, window title, time recorded, and synced (green) or pending (grey).

Usage Summary — total active time, active vs. idle, time by application, and top sites.

Two screens side by side: the raw event log on the left, the rolled-up daily view on the right. This is the clear record of the day that replaces the timesheet.

Wrapping up

Ending a session — two ways.

🖥From the app

Open the status window and choose End Session. A confirmation dialog appears before anything is finalised.

📱On BeeWhere

If the user clocks out on the mobile app, beeWork detects it and ends the session automatically.

When a session ends, the clock-out is recorded and any remaining work log entries are sent to the server.
Two ways out, and one of them requires no action at all — clocking out on mobile closes the loop. The pending counter always returns to zero.

Always current

Updates itself.

  • beeWork checks for updates automatically.
  • An "Update available" dialog appears when a new version ships.
  • Click "Download & Install" — done.

New versions are published to the OTA server; the app picks them up without any manual download.

Tie this to the OTA server: dropping a new build and bumping the manifest pushes it to every installed client. No reinstall, no IT visit.
